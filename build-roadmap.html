Cost tracking per menu — what’s possible now

In the blueprint: Cost family (Costs & Vendors), Budget/Actual/Committed/Forecast/Variance, AI cost drill, and Home “spend” on the status strip. Command schema includes budget/credit ceilings.

What exists in software today:

  • Yes (thin, honest): Home cost strip uses UNAVAILABLE semantics (PR #58). Do not treat a stub $0 as earned spend. PAUSED · writes false. Not per-menu cost accounting.
  • Yes (design only): Post-R3 §29 defines ledgers and drill paths. Not implemented as APIs in apps/factory-os.
  • No (yet): No Factory OS cost/budget API, no vendor connector, no per-menu accrual, no Cursor-usage→menu allocation, no DigitalOcean→menu allocation.
  • Do not fake: Putting dollar fields on every menu before Cost Phase would invent precision. Mark cost cells UNAVAILABLE until Cost menu + metering exist.

Practical next step for cost: keep Home spend as UNAVAILABLE until evidence-backed metering exists. Per-menu cost columns wait for Costs & Vendors Phase (Later) plus run/token metering from Work / AI & Models.

Implementation path when we do Cost: (1) extend Bridge health with optional spend evidence object; (2) add Cost ledger records in Factory DB; (3) attribute via commandId/runId/productId — not by menu label alone; (4) menus show rollups only. Cursor subscription usage and DigitalOcean invoices stay outside Factory OS unless we import them as Vendor cost lines.
